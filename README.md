# 🎡 SEO Keyword Wheel Explorer

> Интерактивное радиальное дерево поисковых запросов, которое работает прямо в браузере на локальных LLM. Без бэкенда, без API-ключей, без серверов.

## 📖 Что это

**SEO Keyword Wheel Explorer** — это исследовательский прототип инструмента для расширения семантического ядра. Вы вводите стартовую фразу (`iphone`, `buy the phone`, `как выбрать матрас`), и инструмент строит **радиальное дерево** связанных поисковых запросов. Клик по любому узлу — новые ветки.

Вся работа с языковой моделью происходит **в браузере пользователя** через [Transformers.js](https://github.com/huggingface/transformers.js) и **WebGPU / WASM**. Никакие данные никуда не отправляются.

### Как это выглядит

- **Центр** — стартовый запрос.
- **Кольца** — уровни расширения. Каждый уровень = 180px.
- **Пунктирные окружности** — подсказки глубины.
- **Клик по узлу** → генерация нового кольца связанных запросов.
- **Auto-fit zoom** — дерево автоматически вписывается в кадр.

## ⚠️ Важно: о размере модели

**Не все модели одинаково полезны для этой задачи.** Инструмент работает с любой инструкционной LLM, поддерживаемой Transformers.js, но качество результата **линейно зависит от размера модели**:

| Модель | Размер | Качество SEO-ядра | Рекомендация |
|---|---|---|---|
| `SmolLM2-135M` | ~270 MB | ❌ Не следует инструкциям, галлюцинирует | Только как быстрое демо механики |
| `Qwen2.5-0.5B` | ~950 MB | ⚠️ Базовое, но рабочее | Минимум для прототипа |
| `Qwen2.5-1.5B` | ~2.5 GB | ✅ Хорошее | **Рекомендую** |
| `Qwen2.5-3B` | ~5 GB | ✅✅ Отличное | Если хватает VRAM |

> 💡 **Совет:** если хотите реальный результат — выбирайте **Qwen 2.5 1.5B или больше**. Модели меньше 0.5B физически не способны следовать инструкции «сгенерируй список похожих запросов».

## 🚀 Быстрый старт

### Способ 1: Просто открыть файл (демо-режим)

1. Скачайте `seo_wheel.html`
2. Откройте в браузере
3. Выберите **Fast Simulation** — работает без загрузки модели и интернета
4. Введите фразу → **Initialize Core**

### Способ 2: Локальный сервер (для реальной LLM)

Браузеры блокируют ES-модули при открытии файла через `file://`. Нужен локальный сервер:

```bash
# Python 3
python -m http.server 8000

# Node.js
npx serve

# VS Code
# Установите расширение "Live Server" → правый клик по HTML → Open with Live Server
```

Затем откройте `http://localhost:8000/seo_wheel.html`.

### Способ 3: Реальная модель

1. Выберите `Qwen 2.5 0.5B` (или 1.5B) в селекторе
2. Введите фразу
3. Нажмите **Initialize Core**
4. Первый запуск скачает модель в кэш браузера (~950 MB для 0.5B)
5. Дальнейшие запуски — мгновенные

**Требования к браузеру:**
- Chrome / Edge 113+ (для WebGPU)
- Firefox / Safari — работает через WASM (медленнее)
- ~2 GB свободной RAM для Qwen 0.5B

## 🧠 Как это работает

```
┌─────────────────────────────────────────────────────────────┐
│  1. Пользователь вводит фразу: "iphone"                     │
│  2. Строим chat-промпт:                                     │
│     system: "Ты SEO-ассистент. Отвечай списком запросов."   │
│     user:   "Generate 8 queries similar to: iphone"         │
│  3. Токенизируем → input_ids + attention_mask               │
│  4. model.generate() → генерирует текст                     │
│  5. Декодируем токены → строка                              │
│  6. Парсим строки → массив запросов                         │
│  7. Фильтруем (стоп-слова + дедуп + длина)                  │
│  8. Строим radial tree через d3.tree() + linkRadial()       │
│  9. Auto-fit zoom → дерево вписывается в кадр               │
│ 10. Клик по узлу → goto 2 с новой фразой                    │
└─────────────────────────────────────────────────────────────┘
```

### Ключевые технические решения

- **`d3.tree()` вместо `d3.cluster()`** — равномерно распределяет узлы по кольцу.
- **Фиксированный `LEVEL_STEP = 180px`** — все узлы на одной глубине на одном радиусе, а не сжаты в центре.
- **Auto-fit zoom после каждой перерисовки** — дерево всегда в кадре.
- **`pipeline('text-generation')` вместо `model.generate()`** — стабильнее в Transformers.js v3.0.0.
- **Мьютекс (`busy` flag)** — блокирует кнопки, пока идёт генерация.

## ⚠️ Известные ограничения

### Технические

- **Скорость на WASM** — если WebGPU недоступен, генерация идёт на CPU, ~2–5 сек на запрос.
- **KV-cache не используется** — при прямой работе с моделью через `model()` каждый шаг пересчитывает всё заново. Решение: использовать `pipeline`, который управляет кэшем сам.
- **Нет стриминга** — ответ приходит целиком, пользователь ждёт 2–15 секунд.
- **Модели не кэшируются между сессиями** — если очистить кэш браузера, модель скачается заново.

### Концептуальные

- **Это не полноценный SEO-инструмент.** Здесь нет:
  - Частотности запросов (Wordstat, Keyword Planner)
  - Конкуренции и CPC
  - Проверки реальной выдачи Google / Яндекс
  - Группировки по коммерческому / информационному интенту
  - Сезонности и локальности

- **Это query expansion** — расширение по ассоциациям модели. Как фича в Key Collector или Serpstat, но без их баз данных.

### Ограничения моделей

- **SmolLM2 135M не годится** для реального SEO-ядра. Слишком слабая, чтобы следовать инструкциям. Используйте её только для проверки механики колеса.
- **Qwen 2.5 0.5B — минимум** для рабочего прототипа.
- **Для продакшена нужен 3B+** или API-модель (GPT-4, Claude).
